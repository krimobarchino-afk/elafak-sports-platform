# إعداد الدخول الإداري ومراجعة طلبات الانضمام

## ما الذي تضيفه هذه المرحلة؟
- حسابات موظفين بأسماء مستخدمين بدل مطالبة أعضاء المكتب ببريدهم الشخصي.
- إدارة كلمات المرور عبر Supabase Auth؛ لا تُخزّن كلمات المرور في جداولنا.
- أدوار منفصلة وحماية RLS لطلبات الانضمام.
- إنشاء حساب المسؤول الأول برمز تهيئة سري، ثم إنشاء حسابات المكتب التنفيذي من خلال وظيفة موثوقة.

## 1. تطبيق قاعدة البيانات
في Supabase → SQL Editor شغّل:
`supabase/migrations/202610170001_staff_auth_and_review.sql`
بعد التأكد من أن migration الخاصة بجدول `join_requests` مطبّقة بالفعل.

## 2. نشر Edge Functions
انشر المجلدين `supabase/functions/staff-login` و`supabase/functions/staff-admin` إلى مشروع Supabase باستخدام Supabase CLI أو واجهة النشر المناسبة. هاتان الوظيفتان لا تُنشران تلقائيًا لمجرد رفع الملفات إلى GitHub.

الإعدادات المطلوبة في أسرار Edge Functions:
- `SUPABASE_URL`
- `SUPABASE_ANON_KEY`
- `SUPABASE_SERVICE_ROLE_KEY` (سر خادمي فقط؛ لا تضعه في Vercel أو المتصفح)
- `BOOTSTRAP_ADMIN_TOKEN` (رمز عشوائي طويل، يستخدم مرة واحدة)

## 3. إنشاء المسؤول الأول
أرسل طلب POST إلى وظيفة `staff-admin` مع:
- ترويسة `x-bootstrap-token` بقيمة `BOOTSTRAP_ADMIN_TOKEN`
- جسم JSON: `{"action":"bootstrap","username":"admin_elafak","full_name":"اسم مسؤول المنصة","password":"كلمة مرور قوية وفريدة من 12 محرفًا على الأقل"}`

لا ترسل رمز التهيئة أو كلمة المرور في المحادثة أو تضعهما في GitHub. استخدم أداة محلية آمنة لإرسال الطلب، ثم احذف `BOOTSTRAP_ADMIN_TOKEN` من أسرار الوظيفة بعد نجاح إنشاء المسؤول. الوظيفة ترفض إنشاء مسؤول أول إذا كان أحدهم موجودًا بالفعل.

## 4. إنشاء حسابات المكتب التنفيذي
بعد تسجيل دخول المسؤول، تستقبل وظيفة `staff-admin` طلبات `create_staff` مع رمز الجلسة في ترويسة Authorization. الأدوار المسموح بها: `president`, `secretary_general`, `treasurer`, `deputy_president`, `deputy_secretary_general`, `deputy_treasurer`. كلمة المرور المؤقتة لا تقل عن 12 محرفًا، ويجب تسليمها للعضو عبر قناة آمنة.

## تنبيهات
- البريد الداخلي `@staff.elafak.invalid` هو معرّف تقني للمصادقة فقط، وليس بريدًا حقيقيًا ولا يحتاجه العضو.
- تسجيل الدخول باسم المستخدم يتم عبر وظيفة `staff-login`، التي تتحقق من أن الحساب نشط قبل إصدار الجلسة.
- لا تجعل جدول `staff_profiles` عامًا ولا تمنح الزوار صلاحية القراءة.
- هذه الملفات وحدها لا تعني أن النظام أصبح منشورًا أو جاهزًا للاستخدام؛ يجب تطبيق migration ونشر الوظائف واختبارها قبل تفعيل الواجهة.
