# تصميم المرحلة التالية: حسابات الموظفين وصلاحياتهم

## الهدف
إنشاء دخول خاص للمسؤولين بأسماء مستخدمين يحددها مدير الموقع، دون اشتراط استعمال بريدهم الشخصي، مع صلاحيات قابلة للتدقيق ومطبقة على الخادم وقاعدة البيانات.

## قرار المصادقة
Supabase Auth القياسي يعتمد البريد الإلكتروني أو الهاتف مع كلمة المرور، ولا يوفر اسم مستخدم مستقلًا كمعرّف دخول مدمج. لذلك لا نبني مصادقة كلمات مرور خاصة بنا ولا نخزن كلمات المرور أو تجزئاتها في جدول التطبيق.

التنفيذ المقترح هو طبقة خادمية صغيرة لاسم المستخدم: تستقبل اسم المستخدم وكلمة المرور عبر HTTPS، تتحقق من الحساب المفعّل، ثم تستخدم آلية Supabase Auth المعتمدة لإصدار جلسة المستخدم. لا تُرسل مفاتيح إدارية إلى المتصفح. يجب أن يكون رد الفشل عامًا حتى لا يكشف وجود اسم المستخدم، مع تقييد محاولات الدخول وتسجيل أحداث الأمان دون تسجيل كلمة المرور.

قبل اعتماد طريقة ربط الاسم بهوية Supabase Auth، يجب التحقق من إعدادات المشروع الحالية وآلية إدارة الحسابات، ثم اختبارها في بيئة آمنة. لا ننشر واجهة دخول شكلية أو نظامًا جزئيًا على الإنتاج.

## بيانات الحساب والصلاحيات
يُحفظ سجل داخلي لكل حساب يتضمن على الأقل: معرّف مستخدم Auth، اسم المستخدم الفريد، الدور، حالة التفعيل، ومن أنشأه وتواريخ التغيير. لا تكون هذه البيانات قابلة للقراءة أو التعديل من الزائر العام.

الأدوار المبدئية:
- الرئيس: مراجعة الطلبات واعتمادها، والاطلاع على الملفات وفق النظام.
- الأمين العام: ملفات الجمعية باستثناء المالية.
- أمين المال: الملفات المالية فقط.
- النواب: صلاحيات الأصيل عند تفويض صريح أو تعذر الأصيل، مع تسجيل التفويض.
- المدير التقني: تقديم المشاريع الفنية للمكتب التنفيذي؛ لا يعتمد التصويت نيابة عن المكتب.
- مدير الموقع: إدارة الحسابات والأدوار التقنية دون تجاوز القرارات الجمعوية المعتمدة.

يجب التحقق من التفويضات والقرارات الحساسة خادميًا، وعدم الاعتماد على إخفاء الأزرار في الواجهة. تُخزّن معلومات الدور في مصدر موثوق لا يستطيع المستخدم تعديلها بنفسه، وتُراجع صلاحية الجلسة عند العمليات الحساسة.

## إنشاء أول مدير
لا توجد طريقة آمنة لتعيين أول مدير من نموذج عام. يجب إنشاء الحساب الأول من قناة إدارية موثوقة في Supabase، ثم ربطه بسجل الدور والتحقق من أن الحساب لا يستطيع رفع صلاحياته بنفسه. لا تُرسل كلمة المرور أو مفاتيح الإدارة عبر المحادثة أو تحفظ في GitHub.

## اختبارات القبول قبل النشر
1. الزائر العام لا يستطيع قراءة طلبات الانخراط أو تعديلها.
2. الحساب غير المفعّل لا يستطيع فتح لوحة الموظفين أو استخدام API الإدارة.
3. المستخدم لا يستطيع تغيير دوره أو تفعيل حسابه بنفسه.
4. أمين المال لا يستطيع قراءة الملفات غير المالية.
5. الأمين العام لا يستطيع قراءة الملفات المالية.
6. الرئيس يستطيع مراجعة الطلبات وفق الصلاحيات المعتمدة.
7. طلب الانخراط لا ينشئ حسابًا تلقائيًا.
8. لا يظهر أي مفتاح سري أو كلمة مرور في ملفات المتصفح أو سجلات Git.
9. تُختبر إعادة تعيين كلمة المرور وتعطيل الحساب وإبطال الجلسات.
10. تُراجع نتائج Supabase Security Advisor بعد تغييرات RLS والسياسات.
